1. Components and data flow

Input is handled on the UI thread, the conversation runs on one worker thread, and speech is produced on a third. The agent is the only part that talks to the chat model; everything it learns about the world comes back as text from the service client or from a tool.

2. One request, step by step

Everything below is Agent::run_turn() in src/agent/agent.cpp. The checks after the model call are drawn in the order the code makes them. The right-hand line returns to the start of the next round; the left-hand line leaves the loop.

The four flags that steer the loop

FlagMeaningChanges
actedA tool has run for the current request. Set after the tool calls of a round; reset when a new request is absorbed after an answer.
guardedA claim guard has already fired for the current request. Set by either guard; reset together with acted.
holdThe reply of this round is kept back until it has been checked. Per round: fast mode, the last message in history_ is not a tool result (deciding), and neither flag above is set.Computed at each round start.
correctionA one-off note for the next model call, written by a guard. Added to that call's copy of the messages with add_note(), then cleared. Never stored in history_.

What the user can do while a request runs

ActionWhenWhat the code does
Speak or type moreBefore anything has been spoken, or while tools run The input waits in inputs_. has_pending() withdraws an unspoken draft; after tool calls absorb_inputs(false) adds it as a further user message, marked as steering on screen. The model then answers the request as amended.
Type moreWhile the answer is being spoken The speech carries on. After the answer the text is absorbed and handled as the next request in the same run_turn() call.
TABWhile it is speaking and the model call is still open interrupt_speech() stops the speech queue, sets interrupted_ and cancels the model call. The text so far is stored with “[the user interrupted here]” and the run ends.
TABAfter the run has ended, with speech still playing Only SpeechQueue::stop().
ESCAny time the agent is busy or speaking cancel(). A tool that has not started yet returns “ERROR: cancelled by the user” so that every tool call in history_ still has a result.

What one model call contains

The order is chosen so that the beginning of the request stays identical from call to call (comments in absorb_inputs() and prompt::system_prompt()): the clock time travels with each user message, not in the system prompt.

System prompt, from prompt::system_prompt() Role and device; “Being right matters more than being quick” (trust rules: nothing happens without a tool call, the camera only through look, changeable facts from web_search, no date or number work in the head); “Using tools” (act at once, ask only when a wrong guess would matter, date formats, the say argument, memory and calendar habits); “How to answer” (one to three spoken sentences, plain text, the user's language); “Today” (time zone, the next fourteen days with weekdays, name, home city, date order, units, size of the music library, whether web search is set up); “What you remember about the user” (every memory from Store::memories() with its id).
history_ User, assistant and tool messages. Each user message starts with [Tue 17 Nov 2026, 14:05], and numeric dates in it have been followed by their meaning in words by util::spell_numeric_dates(), using the day-first or month-first setting.
Notes for this call only (add_note()) kDecideNote when the reply will be held; a guard's correction; “Answer now with what you have” in the last round. A note is appended to the newest user message, or sent as a trailing system message when the last message is not a user message.
Second look only The draft as an assistant message, then kSecondLook as a user message: call the right tool if the draft claims an action, states something a tool provides, or skipped a lookup; otherwise reply “OK”.

Solid border: stored between calls. Dashed border: added to one call and not stored.

From text to sound (src/agent/speech.cpp)

  • SpeechQueue::Chunker::feed() cuts streamed text at ., ! or ? followed by a space once the piece is at least 25 characters long, at a line break, or at a comma, semicolon or space after 240 characters. A full stop between two digits is not a cut.
  • SpeechQueue::enqueue() first passes the sentence through prompt::for_speech(), which removes markdown characters and shortens a link to its domain.
  • SpeechQueue::run() synthesizes one sentence, writes it to the speaker with 120 ms of silence after it, then takes the next. stop() empties the queue, kills the player process and bumps generation_, which the watcher thread turns into a cancelled request within about 20 ms.

3. Tools

22 tools are defined in build() in src/agent/tools.cpp. Each takes JSON arguments and returns text; a failure is text starting with ERROR. tools::run() rejects unknown names and arguments that are not a JSON object, and catches exceptions. Ten tools (kConfirmable) accept a say argument: the sentence to speak once the call has worked. tools::confirmation() returns it only when the result does not start with ERROR or {"error".

The shortcut applies to a round only when every call in it returned a say sentence (all_confirmed), nothing new was said and nothing was cancelled. The sentences are joined, identical ones once, and spoken. Otherwise the model gets another round and writes the answer from the results.

4. Things worth reviewing

Each point was checked in the source named under it. Points marked by reading follow from the code paths but were not run.

Guards against unbacked claims

  • The claim guards match English phrasing. claims_action() is a list of English patterns (“I've added”, “is now in your calendar”, “now playing”, a reply opening with “done” or “got it”) plus a few words in Spanish, German, French, Portuguese and Italian. claims_not_saved() is English only. The system prompt tells the model to reply in the user's language, so in other languages the regex guards rarely apply and the fast-mode second look is the remaining check. src/agent/agent.cpp · claims_action(), claims_not_saved(); src/agent/prompt.cpp · system_prompt()
  • The same patterns can match ordinary sentences. “I put”, “I called”, “I started”, “I set” or “I moved” anywhere in the checked text count as an action claim. The cost is bounded: one withdrawn draft and one extra round, because guarded lets a guard fire once per request. src/agent/agent.cpp · claims_action(), run_turn()
  • Each request is checked once, and only before its first tool call. The hold, the second look and both guards require !acted && !guarded. After a correction the next reply is spoken unchecked, and after any tool has run (for example calendar_list) a later “I've moved it” with no calendar_update is not examined. src/agent/agent.cpp · run_turn()
  • With fast mode off, only the first streamed sentence is checked. Without the hold, claims_action() runs on the first sentence before it is spoken. The whole-reply checks, including claims_not_saved(), run only if nothing was spoken during the stream, which in practice means a one-sentence reply. Fast mode is on by default (Settings::fast_mode). src/agent/agent.cpp · run_turn() (opt.on_text and the checks after llm::chat())
  • The second look only acts on tool calls. Its text is never read: “OK”, any other wording and a failed call all let the draft through (the failure case is deliberate, per the comment). In fast mode every reply without a tool call therefore costs two model calls, and nothing is shown or spoken until both have finished. The comment relies on the server's prefix cache to make the second call cheap. src/agent/agent.cpp · run_turn(), kSecondLook
  • A say confirmation is written before the tool runs and is not compared with the result. Success means the result does not start with ERROR or {"error". What is spoken is the model's sentence, not what was stored: if the day named in say and the start argument disagree, the user hears the former. Anything the result adds, such as the remote's “cannot see whether the TV reacted”, is not spoken on this path. Both the result and the spoken sentence are kept in history_. src/agent/tools.cpp · confirmation(), kConfirmable; src/agent/agent.cpp · run_turn()

Limits and budgets

  • kMaxRounds is not a cap on model calls per request. The comment says “model calls per request”. A second look is an extra call inside a round; a draft withdrawn for steering gives its round back (--round); and input absorbed after an answer becomes the next request in the same loop with acted and guarded reset but the counter kept. src/agent/agent.cpp · run_turn(), kMaxRounds = 8
  • The loop can end without an answer or an error.by reading If the eighth round ends in continue, the loop falls through to end_of_answer() silently. That happens when a guard fires in that round, when its second look returns tool calls that are not all confirmed, or when a follow-up is absorbed after that round's answer; the follow-up then sits in history_ until the next input. Reaching the eighth round needs a long tool chain or several follow-ups in one run, so this should be rare. src/agent/agent.cpp · run_turn()
  • History is limited by message count, at the start of a request only. trim_history() keeps the last 40 messages, starting at a user message. Tool results count as messages and may be 6000 characters each, and nothing is trimmed between rounds, so the size sent is not bounded in bytes. history_ is kept in memory only: nothing in agent.cpp writes it to disk. src/agent/agent.cpp · trim_history(), kMaxHistory = 40, kMaxToolResult = 6000
  • What keeps the prompt prefix stable, and what changes it. Clock time is in the user messages and the “Today” section changes once a day. The system prompt is rebuilt for every model call and lists the memories, so memory_save changes it between two rounds of one request. Once the history is over 40 messages, each new request drops messages from the front. Whether the service caches prefixes at all cannot be seen from this code. src/agent/prompt.cpp · system_prompt(); src/agent/agent.cpp · absorb_inputs(), trim_history()

Failure handling

  • One HTTP 400 switches reasoning_effort off until the app restarts. Any 400 with nothing received while the field was sent sets the static effort_rejected, whatever the reason for the 400. Fast mode keeps its hold and second look, but the model may reason again on every call. mp3_rejected and opus_rejected latch the same way for audio formats. src/agent/llm.cpp · chat(), transcribe(), synthesize()
  • A failed transcription loses the recording. transcribe() retries only with another format, not after a dropped connection (unlike chat()). On an error absorb_inputs() reports “Could not transcribe” and moves on; the samples are gone. src/agent/llm.cpp · transcribe(); src/agent/agent.cpp · absorb_inputs()
  • A failed speech synthesis is silent. SpeechQueue::run() skips a sentence whose synthesis failed and discards the error text. The answer stays on the screen, but nothing says why it was not spoken. src/agent/speech.cpp · SpeechQueue::run()
  • An empty reply is stored as an empty assistant message. The final-answer path appends the assistant message before it checks for empty content and raises “The model returned an empty answer.” src/agent/agent.cpp · run_turn()

Timing and threads

  • An answer can start playing while the microphone is open.by reading start_recording() calls interrupt_speech() once. If the agent is thinking or running a tool at that moment the run carries on, and until the recording is submitted has_pending() is false, so the reply is enqueued and spoken. Music is held by kMic; the speech queue has no such hold. src/ui/app.cpp · start_recording(); src/agent/agent.cpp · interrupt_speech(), run_turn(); src/agent/speech.cpp
  • Alerts share the speech queue and are unknown to the model. Agent::say() enqueues the alert behind whatever sentences are waiting and calls end_of_answer(), even in the middle of an answer. Nothing is added to history_, so “what was that reminder?” has no context. src/ui/app.cpp · check_alerts(); src/agent/agent.cpp · Agent::say()
  • Tools block the agent thread, and two of them ignore cancel. Calls run one after another. HTTP requests stop on Context::cancel; run_python (up to 20 s) and the camera capture in look do not take it. In look the thumbnail callback also runs ffmpeg on the agent thread (up to 8 s) before the photo is sent for analysis. src/agent/tools.cpp · t_python(), t_look(); src/ui/app.cpp · wire_agent() (ev.image)
  • Settings is written from two threads without a lock. The device, tv_remote and set_timezone tools change fields and call save() on the agent thread; the volume and brightness keys do the same on the UI thread. The struct includes <mutex> but has no mutex member. src/core/settings.h; src/agent/tools.cpp · t_device(), t_tv_remote(), t_set_timezone(); src/ui/app.cpp · control_key()
  • A typed request does not hold the music. kExchange is set when a voice request is sent and by the music tool, not by submit_text(). Music keeps playing while a typed request is worked on and pauses when the first sentence is ready to speak. src/ui/app.cpp · finish_recording(), handle_key()
